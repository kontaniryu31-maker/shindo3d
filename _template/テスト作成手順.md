# A4テスト 作成手順（量産マニュアル）

これは「どの教科・どの単元でも、同じ手順で同じ品質のA4テスト練習問題を作る」ための手順書。
**毎回これを見れば、AIが同じ品質で量産できる。** 迷ったらこの順番どおりに進める。

骨組みは `_template/test-template.html` を複製して使う。中身を差し替えるだけ。

---

## 0. まずこれだけ（最短ルート）

1. `_template/test-template.html` を `{教科フォルダ}/test-{単元キー}-{種類}.html` に複製
2. CSS変数 `--accent` を教科色にする（社会=`#9A6A00`／理科=`#168a68`／算数=`#2F6FB0`）
3. 後述の「作成プロセス(1)〜(5)」で中身を作る
4. ヘッドレスChromeでPDF化して「問題1枚＋答え1枚＝2ページ」を実測確認
5. **★最重要★ その教科の進度表 index.html の「いんさつテストのたな」に1行追加**（やり方は §5）

---

## 1. 「1単元＝5種メニュー」の型

1つの単元につき、下の5種から単元に合うものを選んで作る。全部作る必要はない（取捨する）。

| 種類 | キー | 観点 | 何を測るか | 種類バッジ |
|---|---|---|---|---|
| ①たしかめ | `kihon`（または単元名） | 知識・技能 | 用語・事実・基本の理解 | `📘 きほん` |
| ②記述・推論 | `kijutsu` | 思考・判断・表現 | 短い理由・説明を書く | `✏️ きじゅつ` |
| ③資料問題 | `shiryou` | 思考・判断・表現 | 表・グラフ・カードを読みとる | `📊 しりょう` |
| ④深い学び | `fukai` | 思考・判断・表現（見方・考え方） | 資料から考えて説明する | `🧠 深い学び` |
| ⑤まとめ | `matome` | 知技＋思判表 | 単元全体のまとめ | `🏁 まとめ` |

- **取捨の目安**：知識中心の単元は①③⑤、考えさせたい単元は②④を足す。
- お手本ファイル：
  - ① 知識型 → `rika/test-shokubutsu.html`
  - ③ 資料型 → `rika/test-sodachi-shiryou.html`
  - ④ 深い学び・記述推論型（最新の到達点）→ `shakai/test-fukai.html`

## 2. 作成プロセス（必ずこの順）

### (1) "型"だけ参照（文章の丸写し禁止）
- Driveの業者テスト（教科書準拠ワーク等）を見て、**出題の型・観点配分・配点感だけ**を参照する。
- **問題文・図・数値の丸写しは禁止。** あくまで「どんな問い方をするか」の参考。

### (2) 確認できた事実だけで作問
- 教科書・確かな資料で**確認できた事実だけ**を使う。未確認のことは出さない。
- **数値は概数＋注記**にする（例：「約15度」「※およその数」）。実在の固有名・時刻表などを断定で書かない（「れいです」と注記）。

### (3) 全問オリジナル作文
- 問題文・選択肢・記述例・解説・資料（SVG/表）は**すべて自分で書き起こす**。
- 記述問題の答えは「（れい）」とし、`✓ここが書けていれば◯`＋`なども正解`＋`💡つまずきポイント`をセットで付ける。

### (4) ヘッドレスChromeでPDF実測 → 2ページに収める
- 下のコマンドでPDF化し、**「問題1枚＋答え1枚＝2ページ」**に収まっているか実測する。

```bash
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
F="/Users/kontaniryu/claude obsidian/shindo3d-portal/{教科}/test-{単元キー}-{種類}.html"
"$CHROME" --headless --disable-gpu --no-pdf-header-footer \
  --print-to-pdf="/tmp/test_check.pdf" "file://$F"
# ページ数を数える（2なら合格）
python3 -c "import re,sys; d=open('/tmp/test_check.pdf','rb').read(); print('pages=', len(re.findall(rb'/Type\s*/Page[^s]', d)))"
```

- **3ページ以上にあふれたら**：大問を減らす／記述らんの `min-height` を下げる／`.q` の `padding` や `font-size` を少し詰める／資料SVGの高さを下げる。
- 余白が大きすぎて1ページに問題が収まりきらない場合は、逆に1問増やすか余白を活かす。

### (5) 全漢字ふりがな検証
- **すべての漢字に `<ruby>漢字<rt>かな</rt></ruby>` を付ける**（送りがなはruby外。例：`<ruby>育<rt>そだ</rt></ruby>ち`）。
- 答えページの本文・解説も同様。`<rt>` の付け漏れがないか目視＋検索でチェック。
- チェック用（ふりがな無しの漢字が残っていないか機械的に当たりを付ける）：
```bash
# rt を含まない行のうち、CJK漢字が出てくる箇所をざっと洗い出す目安
grep -nP '(?![^<]*<rt)[一-龯]' "$F" | head
```
（完全自動判定は難しいので最後は目視。タイトル・選択肢・解説まで漏れなく。）

## 3. 命名規則

```
{教科フォルダ}/test-{単元キー}-{種類}.html
```

- 例：`shakai/test-fukai.html`、`rika/test-sodachi-shiryou.html`、`rika/test-shokubutsu.html`
- 種類が単元名そのもの（基本テスト）のときは `-{種類}` を省くこともある（例：`test-shokubutsu.html`＝植物の基本）。
- 資料問題は `-shiryou`、深い学びは `-fukai`、まとめは `-matome` を付けると一覧で種類が分かる。

## 4. 教科ごとの色とトーン

CSS変数 `--accent` を1か所替えるだけで全体がそろう（`.lead` 背景・`.rtable th` 背景も合わせると完璧）。

| 教科 | --accent | .lead / th 背景 | トーン |
|---|---|---|---|
| 社会 | `#9A6A00`（金茶） | `#FBF3E7` | 進度表はシンプル版（RPG装飾なし）。せつめい＝推論記述 |
| 理科 | `#168a68`（緑） | `#EAF6F1` | 観察・記録・予想のすじ道を重視 |
| 算数 | `#2F6FB0`（青） | `#EAF1F8` | 式・説明・図を書かせる |

### 社会の標準（特記）
- 進度表は**シンプル版**（RPG装飾なし）。
- 「せつめい」問題＝**推論記述**。**社会的見方・考え方**を働かせる問いにする：
  - **位置／空間的な広がり**（どこに・なぜそこに）
  - **時間的な経過**（むかし→いま・受けつぎ）
  - **相互関係**（人と土地・交通とくらし のつながり）
- 「資料からわかること」＋「だから、こうなる」を**つなげて書かせる**のが軸（`test-fukai.html`が見本）。

## 5. ★最重要ルール★ 作ったら必ず「いんさつテストのたな」に1行追加する

**テストを1本作ったら、必ずその教科の進度表 `index.html` の「いんさつテストのたな」に1行足す。**
たなが無ければトップページ（ルート `index.html`）に入れる。これを忘れると子どもが辿り着けない。

### たなの場所
- `rika/index.html` … `いんさつテストのたな` の配列（だいたい 947行目あたり）
- `shakai/index.html` … 同（だいたい 813行目あたり）
- 目印で探す：ファイル内を `いんさつテストの たな` または `test-` で検索。

### 追加方法（配列に1行足すだけ）
たなは次の形の配列で、各行が `[ファイル名, 番号, ラベル, 種類バッジ]`：

```jsx
{[
  ["test-shokubutsu.html", "①", "しょくぶつの かんさつ（たね・育ち・体）", "📘 きほん"],
  ["test-konchu.html",     "②", "チョウと こん虫（かいて せつめい）",       "✏️ きじゅつ"],
  // …
  ["test-あたらしいファイル.html", "⑦", "あたらしいテストのラベル", "🧠 深い学び"],  // ← この1行を足す
].map(([url, no, label, kind]) => ( … ))}
```

- **番号**は丸数字（①②③…）で連番。
- **種類バッジ**は §1 の表のものを使う（`📘 きほん`／`✏️ きじゅつ`／`📊 しりょう`／`🧠 深い学び`／`🏁 まとめ`）。
- ラベルは子ども向けに短く。漢字には基本ふりがな（たなは `rb()` でルビ自動付与の場合あり＝既存行に合わせる）。
- 追加したら index.html もブラウザで開いて、たなに行が増えてリンクが開くか確認。
- ⚠️ 注意：portal の index.html がライブ（正）。`game/` からのコピーは厳禁（古い版に巻き戻る）。
